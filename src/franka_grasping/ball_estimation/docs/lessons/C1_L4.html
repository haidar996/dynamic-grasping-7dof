الصنف Sensor: إضافة الـ noise

جواب السؤال السابق: R = [[6.73, 2.85], [2.85, 8.39]] mm2 (أي 4.59 + 2.4352 × 0.36 = 6.73، و4.59 + 5.93 × 0.64 = 8.39، والتغاير 5.93 × 0.48 = 2.85) وهي تطابق الجدول.

1. الإعدادات: SensorParams

@dataclass
class SensorParams:
    fps: float = 60.0         delay: float = 0.0
    k_depth: float = 0.0      # depth noise sigma_Z = k_depth * Z^2   (0 = off)
    jitter_px: float = 0.0    # std of the pixel-centroid jitter       (0 = off)
    quant_step: float = 0.0   loss_rate: float = 0.0   ...
    seed: int = 0

كل عيب مغلق افتراضياً (القيمة 0). والشروط الستة في dataset.py تفتح بعضها فقط: مثلاً شرط الـ noise: SensorParams(k_depth=8.2e-4, jitter_px=0.3).

2. تطبيق الـ noise (داخل Sensor.apply)

u, v, z = parts                                   # ideal (u, v, z) from the stored file
if self.p.jitter_px > 0:
    u, v = np.array([u, v]) + self.rng_noise.normal(0.0, self.p.jitter_px, 2)
xy = self.cam.back_project(u, v, self.corrupt_depth(z))
self.last = xy
return xy, True, False

def corrupt_depth(self, z):
    if p.k_depth > 0:
        z = z + self.rng_noise.normal(0.0, p.k_depth * np.asarray(z) ** 2)
    ...
    return z
  • الترتيب مهم: نضيف الـ jitter إلى (u, v) ونضيف خطأ العمق إلى z، ثم نحوّل بالإسقاط العكسي إلى (x, y). ولهذا خطأ العمق يظهر خطاً (الاشتقاق في C1) وهو يتغير مع المكان.
  • الـ jitter: رقمان N(0, 0.32) (واحد لكل من u وv).
  • العمق: رقم واحد بانحراف k z2 (يعتمد على z المقيس نفسه).
  • self.last = xy: نحفظ آخر قياس لنستعمله في الانقطاع الصامت (C4).
  • الدالة تعيد (xy, valid, was_lost): المكان والصلاحية والعلامة الخفية للإطار الضائع.

3. مولّدان عشوائيان منفصلان

self.rng_loss  = np.random.default_rng([params.seed, 0])
self.rng_noise = np.random.default_rng([params.seed, 1])

واحد للانقطاعات وواحد للـ noise. فائدته: لو غيّرنا قوة الـ noise فإن أماكن الفجوات لا تتغير (لأنها تأتي من مولّد آخر بنفس البذرة)، فنقارن الشروط المختلفة على نفس الفجوات (paired، A5).

وفي apply_condition: البذرة = رقم الإطلاق (أو إزاحة منه)، فكل estimator يرى الأرقام العشوائية نفسها لنفس الإطلاق.

4. ملاحظتان

  • الـ noise يُطبَّق على الأرقام المخزنة (u, v, z) في ملفات الإطلاق، فلا نحتاج إعادة رسم. هذا ما يجعل كل شرط يُحسب في ثوانٍ.
  • كل إطار يستهلك أرقاماً من المولّد بالتسلسل. لذلك تغيير ترتيب الاستدعاءات (مثلاً إضافة سحب جديد قبل الـ noise) يغيّر أرقام الإطارات اللاحقة. هذا جيد للإعادة (reproducibility) لكن يجب الانتباه عند تعديل الكود.
