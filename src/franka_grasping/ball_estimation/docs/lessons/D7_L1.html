الدرس D7 · الطبقة 1: سياسات الرفض (Rejection Policies)

ماذا نفعل حين يرفع الـ Gate قياس؟

جواب سؤال D6 L2: الفرق 4% في P[2,2] صغير، لكن يؤثر على K = P·Hᵀ/(H·P·Hᵀ + R) بشكل غير خطي. K يزيد بنسبة أكبر من 4%. بعد الارتداد، K الأكبر يعني تصحيح أقوى → السرعة تتغير أسرع نحو الاتجاه الصحيح → تعافي أسرع. التأثير تراكمي عبر عدة خطوات.

1. المشكلة المرة أخرى

الـ Gate (chi-square test) يقول: "هذا القياس مريب جداً، رفضه".

لكن ماذا بعدها؟ لدينا خيارات:

  • تجاهل القياس وانتظر القياس التالي (policy = "skip")
  • أعد ضبط المرشح من الصفر (policy = "reset")
  • غيّر الاستراتيجية بناءً على عدد الرفضات (policy = "hybrid")
  • لا تستخدم gate على الإطلاق (policy = "none")

2. السياسة الأولى: policy = "none"

القاعدة: لا gate على الإطلاق. قبل كل قياس مهما كان.

المميزات:

  • بسيط جداً—بدون فحوصات
  • يثق بالقياسات (حتى السيئة)

العيوب:

  • قياس سيء واحد يفسد التقدير
  • عند الارتداد، يرى تغيير مفاجئ (outlier) → انجراف

متى تستخدم: الكاميرا موثوقة جداً (مثل روبوت صناعي بكاميرا مغلقة مع ضوء ثابت)

3. السياسة الثانية: policy = "skip"

القاعدة: إذا رفع الـ Gate القياس، تجاهله وانتظر الخطوة التالية.

التطبيق:

if test_statistic > gate:
  return # تجاهل، لا تحديث
else:
  تحديث طبيعي

المميزات:

  • يرفع القياسات السيئة
  • المرشح يستمر بتنبيؤه (بدون تصحيح)

العيوب:

  • إذا كانت قياسات سيئة متتالية (كاميرا متجمدة)، لا تصحيح، المرشح ينجرف
  • بدون أي قياس "جيد"، التنبيؤ وحده يخطئ أكثر فأكثر

متى تستخدم: القياسات السيئة نادرة (عطل مفاجئ كل عدة دقائق)

4. السياسة الثالثة: policy = "reset"

القاعدة: إذا رفع الـ Gate القياس، أعد ضبط المرشح من الصفر:

if test_statistic > gate:
  s = [z_x, z_y, 0, 0] # موقع من القياس، سرعة صفر
  P = P0 # تباين أولي
else:
  تحديث طبيعي

المميزات:

  • إذا حدث شيء مجهول (قفزة)، نبدأ من جديد
  • نثق بالقياس الجديد كنقطة انطلاق

العيوب:

  • نفقد كل ما تعلمناه (السرعة، الثقة)
  • سرعة نُفترض صفر (خطأ غالباً)
  • إذا كانت قياسات سيئة متتالية، نعيد ضبط كل مرة (مزعزع)

متى تستخدم: القياسات السيئة تشير إلى تغيير حاد (الروبوت تحرك، الكاميرا أُزيحت)

5. السياسة الرابعة: policy = "hybrid" (الأفضل)

القاعدة: حاول "skip" أولاً. إذا فشلت قياسات متتالية، انتقل إلى "reset":

fails = 0 # عداد الرفضات المتتالية

if test_statistic > gate:
  fails += 1
  if fails >= k_reset (مثل 3): # 3 رفضات متتالية
    reset() # أعد ضبط
  else:
    return # skip فقط
else:
  fails = 0 # عاد قياس جيد، أعد العداد
  تحديث طبيعي

المميزات:

  • قياس سيء واحد؟ skip فقط (بدون فقدان التعلم)
  • قياسات سيئة متتالية (كاميرا متجمدة)؟ reset (نبدأ من جديد)
  • توازن بين الثبات والمرونة

العيوب: أعقد قليلاً

متى تستخدم: البيئات الحقيقية مع خليط من الأخطاء (متقطعة ومفاجئة)

6. المقارنة: سيناريو بـ 3 رفضات متتالية

السياسة بعد الرفع الأول بعد الرفع الثالث
none قياس سيء يفسد الحالة فوضى تامة
skip تجاهل، تنبؤ فقط تنبؤ صار بعيد جداً، انجراف
reset reset ← أعد ضبط reset ← أعد ضبط (مزعزع)
hybrid skip ← انتظر قياس جيد reset ← عدد > k_reset

7. في الكود

if self.policy != "none" and y @ np.linalg.solve(S, y) > self.gate:
    self.n_gate += 1
    self.fails += 1
    if self.policy == "reset" or (self.policy == "hybrid" and self.fails >= self.k_reset):
        self._reset_to(t, z)
    return  # skip: لا تحديث
self.fails = 0  # قياس جيد، أعد العداد

self.k_reset افتراضي 3 (رفضات متتالية قبل reset).

سؤال للتأكد

إذا استخدمنا policy = "hybrid" مع k_reset = 2 بدلاً من 3، ماذا يحدث؟ هل يصير أفضل أو أسوأ؟

القادم: D7 الطبقة 2 (مثال: قياسات سيئة متتالية، والسياسات تتصرف).
