الدرس B1 · الطبقة 4: أين هذا في الكود

الصنف Pinhole

جواب السؤال السابق: X = 100 × 2.97 / 415.7 = 0.714 m.

1. الكود (ملف sensing/camera.py)

class Pinhole:
    def __init__(self, height=3.0, fovy=60.0, width=640, rows=480, radius=0.03):
        self.W, self.R, self.radius = width, rows, radius
        self.cx, self.cy = (width - 1) / 2, (rows - 1) / 2
        self.set_geometry(height, fovy)

    def set_geometry(self, height, fovy):
        self.H, self.fovy = height, fovy
        self.f = (self.R / 2) / np.tan(np.radians(fovy) / 2)

    def back_project(self, u, v, z_surface):
        zc = z_surface + self.radius                 # surface -> centre
        return np.array([(u - self.cx) * zc / self.f,
                         -(v - self.cy) * zc / self.f])      # rows grow downward

2. شرح السطور

  • self.W, self.R: عرض الصورة (640) وعدد صفوفها (480). self.radius: نصف قطر الكرة 0.03 م.
  • self.cx, self.cy: مركز الصورة (319.5, 239.5) (الدرس B1 L2).
  • set_geometry: تضبط الارتفاع H وزاوية الرؤية، وتحسب f = (R/2)/tan(fovy/2) (415.69 عند 60°).
  • back_project(u, v, z_surface): تأخذ بكسل (u, v) وعمق السطح الذي قاسته الكاميرا، وتعيد مكان مركز الكرة في العالم:
    • zc = z_surface + radius: الكاميرا تقيس بُعد قمة الكرة (2.94 م)، ونحن نريد بُعد المركز (2.97 م)، فنضيف نصف القطر.
    • x = (u − cx) · zc / f (المعكوس من B1 L3).
    • y = −(v − cy) · zc / f: إشارة سالبة لأن الصفوف تزداد نحو الأسفل بينما y العالم يزداد نحو الأعلى في الصورة.

تحقق: back_project(cx + 100, cy, 2.94) يعطي x = 0.7145 m, y = 0. وback_project(cx, cy − 70, 2.94) يعطي x = 0, y = 0.5001 m: صف أصغر (أعلى الصورة) يعني y موجباً.

3. لماذا Pinhole منفصل عن DepthCamera؟

الصنف DepthCamera يرث من Pinhole ويضيف الجزء الذي يحتاج MuJoCo (رسم الصورة، كشف الكرة). أما Pinhole فهندسة فقط، بلا نافذة رسم، فيصلح للاستعمال داخل العمليات المتوازية (worker processes) التي تطبّق الـ noise على الملفات المخزنة. هذا ما استعملناه في التجارب كلها: كاميرا Pinhole(3.0, 60.0) تحوّل (u, v, z) المخزنة إلى (x, y).

ومن التفاصيل التي تعلمناها بالخطأ: إنشاء mujoco.Renderer جديد لكل كاميرا أفسد الصور اللاحقة (أخطاء بالأمتار)، فأصبح هناك renderer واحد يُعاد استعماله، وتُغيَّر الإعدادات بالدالة configure(height, fovy).

4. ربط الكاميرا بالمشهد والملفات

  • الكاميرا في arena.xml: pos="0 0 3" fovy="60". وبدون تحديد اتجاه تنظر MuJoCo إلى الأسفل مع أن «أعلى الصورة» هو الاتجاه +y و«يمين الصورة» هو +x (وهذا ما افترضناه في الإشارات أعلاه، وتحققنا منه بالأرقام في B1 L3).
  • كل ملف إطلاق يحفظ cam_height وcam_fovy. والدالة apply_condition تتحقق (assert) أن كاميرا الاستعمال تطابقهما، وإلا ترفض. هذا يمنع الخطأ الصامت لو غيّرنا الكاميرا وبقيت الملفات القديمة.
